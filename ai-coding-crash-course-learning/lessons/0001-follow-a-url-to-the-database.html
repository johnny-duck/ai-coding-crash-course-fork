Lesson 0001 · ~15 min · Navigating the repo

Follow a URL to the database

This repo has controllers, services and an ORM, like a Spring app. They just live in different places.

Your win today Pick any URL in the app and name, within a minute, the file that handles it, the function that loads its data, and the service it calls. That's what you need to give Claude Code a precise prompt.

1 · The big pictureOne request, five layers

When the browser asks for /courses/intro-to-react, this is what runs. Green layers run only on the server. The red one runs on the server and in the browser.

  1. app/routes.tsRoute table Matches the URL pattern courses/:slug to a file. ≈ all your @RequestMappings collected in one list
  2. app/routes/courses.$slug.tsxloader() Reads params.slug, calls services and returns a plain object. ≈ a @GetMapping method that builds the model
  3. app/services/courseService.tsService functions getCourseBySlug(slug), plus the rest of the business logic. Each service has a .test.ts next to it. ≈ a @Service class
  4. app/db/schema.ts + drizzle/Drizzle ORM → SQLite Tables are defined in TypeScript and queried with a SQL-shaped API. The file data.db is the database. ≈ entities + Flyway migrations, queried jOOQ-style
  5. same file: export defaultComponent Gets the loader's return value as loaderData and returns the HTML (JSX). ≈ the Thymeleaf template, if you squint

The surprising part: the "controller" and the "view" are in the same file. React Router calls this a route module: "The files referenced in routes.ts are called Route Modules." Its loader is "only called on the server" (docs), so a file in app/routes/ can safely call the database.

2 · Your Spring mapAnalogies, and where each one breaks

In this repoSpring equivalentWhere it breaks
app/routes.ts@RequestMapping tableIt's one explicit list, not annotations scattered across classes.
export async function loader@GetMappingIt returns data, not a view name. The default-export component in the same file always renders it.
export async function action@PostMappingAfter it runs, React Router automatically re-runs the loaders on the page (docs).
app/services/*.ts@ServiceNo beans and no DI. They're plain exported functions, and routes import them directly.
Drizzle (schema.ts)JPA @EntityNo entity manager, lazy loading or dirty checking. It's closer to jOOQ: "If you know SQL, you know Drizzle" (docs).
drizzle/0000_*.sqlFlyway migrationsHolds up well. They're generated from schema.ts by npm run db:generate.
default-export componentThymeleaf templateIt renders on the server, then runs again in the browser so that clicks and state work. Templates never do that.
In Spring, "is this server code or browser code?" is decided by which project a file is in. Here it's decided by which export in the same file you're looking at. loader/action run on the server. The component runs in both places. Files named *.server.ts (for example app/lib/markdown.server.ts) are server-only.

3 · Read a real oneapp/routes/courses.$slug.tsx, trimmed

The file name follows the URL: . means / and $slug means :slug. That's a naming convention in this repo. The actual mapping is the line in routes.ts:

// app/routes.ts
route("courses/:slug", "routes/courses.$slug.tsx"),
// app/routes/courses.$slug.tsx
import { getCourseBySlug, getCourseWithDetails } from "~/services/courseService";
//       ^ "~/" is an alias for app/ (like a package root)

export async function loader({ params, request }: Route.LoaderArgs) {
  const course = getCourseBySlug(params.slug);       // :slug from the URL
  if (!course) {
    throw data("Course not found", { status: 404 });  // ≈ ResponseStatusException
  }
  ...
  return { course: courseWithDetails, enrolled, progress, ... };  // ≈ the model
}

export default function CourseDetail({ loaderData }) {
  // JSX: HTML-like syntax that reads loaderData.course.title etc.
}

And the service it calls is plain Drizzle. Read it as SQL:

// app/services/courseService.ts
export function getCourseBySlug(slug: string) {
  return db.select().from(courses).where(eq(courses.slug, slug)).get();
}   // SELECT * FROM courses WHERE slug = ? LIMIT 1
