Lesson 0002 · ~15 min · Reviewing UI diffs

Read a component like a Java method

Five patterns cover nearly everything inside a route's export default.

Your win today Look at a component Claude wrote or changed and say what it renders, under which condition, and where each value comes from. You'll also be able to spot one classic bug without knowing React.

In Lesson 1 you followed a URL down to the database. The loader's return value comes back up as loaderData. This lesson is about the last stop: the component that turns it into HTML.

1 · The one ideaA component is a function that returns markup

Here's the real dashboard from app/routes/dashboard.tsx (line 104), trimmed:

export default function Dashboard({ loaderData }: Route.ComponentProps) {
  const { inProgressCourses, completedCourses } = loaderData;  // destructuring
  const totalCourses = inProgressCourses.length + completedCourses.length;

  return (
    <div className="mx-auto max-w-7xl p-6">
      <h1 className="text-3xl font-bold">My Dashboard</h1>
      ...
    </div>
  );
}

That's the whole model. It's a plain function: data comes in as a parameter and markup goes out as the return value. The HTML-looking part is JSX, "a syntax extension for JavaScript that lets you write HTML-like markup inside a JavaScript file" (react.dev). It isn't a string. It's an expression the compiler turns into function calls.

Two things you can skim past:

  • className="mx-auto p-6 …" is styling (Tailwind CSS classes). It's className rather than class because "class is a reserved word" (react.dev). Styling is out of scope for your mission, so read straight past it.
  • const { a, b } = loaderData is destructuring: shorthand for const a = loaderData.a; const b = loaderData.b;.

2 · Five patternsEach one has a Java twin

①{expression}: print a value

Java

"Progress: " + course.progress() + "%"

JSX

<span>{course.progress}%</span>

Curly braces "open a window to JavaScript", and "any JavaScript expression will work between curly braces" (react.dev). Inside an attribute it works the same way: to={`/courses/${course.courseSlug}`}. The backtick string with ${…} is a template literal, like Java's String.formatted.

The double braces in style={{ width: "40%" }} aren't special syntax. They're a JS object literal { width: … } inside the window { }.

②cond ? <A/> : <B/>: if / else

{totalCourses === 0 ? (
  <div>No enrolled courses … <Button>Browse Courses</Button></div>
) : (
  <div> …the course sections… </div>
)}

It's the same ternary as Java. JSX has no if statement in the markup, so this is how you write if/else (react.dev). A trick that helps: find the ? and the :, and read the two branches as two separate screens.

③cond && <A/>: if, else nothing

{completedCourses.length > 0 && (
  <section><h2>Completed</h2> … </section>
)}

"If cond, render <A />, otherwise nothing" (react.dev).

In Java, && always gives you a boolean. In JS it gives you one of its operands. With count && <p>…</p>, when count is 0 the expression evaluates to 0, and "React will happily render 0 rather than nothing" (react.dev). The fix is to make the left side a real boolean: count > 0 && …. This repo does it correctly. Check for it in every diff Claude gives you.

④list.map(x => <X key={…}/>): a loop

Java

courses.stream()
  .map(c -> renderCard(c))
  .toList();

JSX

{inProgressCourses.map((course) => (
  <Card key={course.enrollmentId}>
    {course.courseTitle}
  </Card>
))}

=> is Java's ->. Each item needs a key, "a string or a number that uniquely identifies it among other items in that array". That's how React matches items up when the list changes. "Index as a key often leads to subtle and confusing bugs", so "use a stable ID based on the data" (react.dev).

A Java stream has nothing like key. Your rule when reviewing: key={item.id} is fine. key={index} deserves a second look.

⑤<Capitalized>: someone else's component

Lowercase tags such as <div>, <span> and <h1> are plain HTML. Capitalized tags are components, which means they're functions, so check the import lines to find where each one is defined:

TagImported fromWhat it is
<Card>, <Button>~/components/ui/*Building blocks that live in this repo (shadcn/ui)
<Link to="…">react-routerAn <a href> that navigates without a full page reload
<PlayCircle>, <BookOpen>lucide-reactIcons

Attributes on a component (<Button variant="outline">) are called props. They're the arguments to that function, just as { loaderData } is the argument to Dashboard.

4 · Do it in the repoRead the in-progress card (4 min)

Open app/routes/dashboard.tsx and scroll to inProgressCourses.map (around line 145). Skip every className.

  • Find the <CardFooter>. It has a ternary. What's the condition, and what are the two button labels?
  • Find the progress bar. Which value sets its width, and through which pattern?
  • Pick one value printed in the card, such as course.completedLessons, and say which service it ultimately comes from. Check the loader at line 20.
Check your answer
  • The condition is course.nextLessonId ? … : …. If there's a next lesson, the button says Continue Learning and links to /courses/:slug/lessons/:id. Otherwise it says View Course.
  • The width comes from style={{ width: `${course.progress}%` }}. That's pattern ① inside an attribute: an object literal holding a template literal.
  • The completed and total lesson counts come from getCompletedLessonCount and getTotalLessonCount in progressService. The loader calls them and puts the results into each course object.

5 · SteerUI changes usually need a data change too

Say you want each in-progress card to show "Last studied: 3 days ago". The component can only print what's in loaderData, so a good prompt names every layer:

On /dashboard, show "Last studied: <relative date>" on each in-progress
card (app/routes/dashboard.tsx, inside inProgressCourses.map).
The data isn't in loaderData yet: add it in the loader, sourced from a
function in app/services/progressService.ts, with a test in
progressService.test.ts. Keep data fetching out of the component.

Then review the JSX part of the diff with these questions:

  1. For every new {value}, can you trace it back to loaderData → loader → service?
  2. For every new &&, is there a number on the left? If so, there's a stray 0 waiting to happen.
  3. For every new .map, is key a stable id rather than the index?
  4. Is className the only noise? Skip it.
